## 新しいルール

- **現在HP・MP**：本人が入力。イベント報酬では一切変更しません。設定ミスで現在HP/MPの報酬を記述しても、イベント適用処理が無視します。
- **最大HP・MP**：イベントで2人同時に成長。以前の成長量を維持し、HP100・MP80に固定しません。
- **幸福度**：イベントで現在値が増加。同時に最大値も成長し、100の上限で止まらないようにします。
- **空腹度**：以前と同じく食事で減少し、0未満にはなりません。
- 夜の4項目の手動入力・日付別記録は維持します。手動で幸福度を変えた場合、最終値もその分変わります。

## 既存セーブへの影響

- 保存キー`reward-quest-device-v4`、保存形式version 2は変更しません。旧キーも削除しません。
- **保存済みの現在値・最大値・達成・夜の記録・持ち物・旅程は自動で書き換えません。** 新しい初期値は数値のセーブがない端末だけに適用します。
- 過去に自動回復した現在HP/MPを差し引いたり、初期値を下げたりしません。
- 達成済みIDには再加算しません。新しい報酬を使うのは未達成イベントだけです。旧報酬との差額の自動精算や幸福度1,000への自動補正はしません。
- 過去のrewardHistory（balance 2）は保持し、新しい達成だけbalance 3で実際の報酬を記録します。
- 途中のセーブや手動調整済みの幸福度では、終盤の幸福度が1,000と一致するとは限りません。

## 新婦用：旅行前の現在値を明示的に設定

既存端末でも開始時の疲労や幸福度を調整したい場合、`?role=bride` → SYSTEM → **旅行前の現在値を設定** → **2人の現在値を確認・設定** を開きます。

最初に表示するのは保存済みの数値です。6つのスライダーで2人の現在HP/MP/幸福度を調整し、**入力した現在値を保存** を押したときだけ保存します。キャンセルすれば何も変わりません。最大値・空腹度・達成履歴・持ち物を変更する操作ではありません。

利用できるのは実際の日本時間で2026年10月31日10:00より前、かつイベント達成・クエスト達成・夜の記録が一つもない場合だけです。デモ時計を巻き戻しても利用条件は変わりません。旅行開始後や達成済みの場合は、従来の夜のステータス入力を使ってください。

各端末の保存は独立しています。新婦URLを自分の端末で開いても、相手の端末には反映されません。新郎の端末の開始値を調整する場合は、その端末で一時的に新婦URLを開いて保存後、新郎URLに戻します。URLのroleは表示用で、認証機能ではありません。
