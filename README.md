# 結婚式お疲れ様旅行 — クリア後のごほうびクエスト
スマホ向け旅行RPG。HTML/CSS/JavaScript、依存パッケージなし、Node.js 20以上。

## Windowsで確認する
作業ブランチ `feat/reward-quest-prototype` の `reward-quest-preview.html` を開き、右上の **Download raw file** でダウンロードしてEdge/Chromeで開きます。インストールは不要です。保存ファイルの場所やブラウザが変わると端末データが引き継がれない場合があります。

SETTINGSで新婦/新郎を切り替えます。デモ日時を旅行中に変更してHOMEへ戻ると、時刻に応じた行程と未確認通知を体験できます。デモ時計は指定した時刻から進みます。

## 起動・テスト・ビルド
```sh
npm run dev
# http://localhost:5173
npm test
npm run build
node scripts/serve.mjs --dist
# 単体HTMLだけ更新
npm run preview:html
```
ビルド成果物は `dist/`。HTMLプレビューも同時に更新します。自動公開・自動デプロイはありません。開発サーバーはsrc/とassets/配下の必要なファイルだけを配信します。

## 保存と表示モード
**localStorageだけを使用します。ログイン・クラウド・サーバー認可は実装しません。端末間は独立です。** 2人への共有イベント効果は、その端末内に保存された2人のステータスに適用します。

ユーザーの今回の指示により、実際の旅行情報をJavaScript/HTMLプレビューに収録しています。新郎モードは画面上のネタバレ防止であり、ソース閲覧に対する秘密保護ではありません。

新婦モードでは全詳細を最初から表示し、QUESTの各行「編集」から時刻・詳細・公開前の行動・補足・解放時刻を編集できます。クエスト名と解放時刻も変更できます。編集はこの端末に保存し、他の端末やGitHubソースには反映しません。

新郎モードでは訪問予定時刻より前の場所名を「？？？」に置き換えます。訪問済みの駅名は帰路でも表示します。NEXT ACTION、QUEST、注記、通知は同じ表示関数を使います。交通手段や時刻は先に確認できます。新婦が自由文を編集した行は、指定解放時刻まで「公開前の行動・補足」を使用します。

## 旅行計画と編集
- `src/itinerary.js`：実旅程の初期値。各行は固定ID、DAY、time、detail、safeText、note、safeNote、revealTime、questIdを持ちます。クエストは行IDをまとめます。
- `src/data.js`：初期ステータス・持ち物・イベント効果、便の候補切り替え、場所名と初回訪問行IDの対応。
- `src/domain.js`：数値処理、ネタバレ防止、NEXT ACTION、通知、達成記録、旅程編集。
- `src/storage.js`：端末内の保存処理。旧保存データを引き継ぎます。
- `src/app.js`：5画面、編集画面、モーダル、チェックリストの部分更新。
- `src/visuals.js`：静止PNGとゲームアイコン。

DAY2は今回指定の時刻を初期値に使用。清里ピクニックバスの区間ごとに北部周遊/大泉周遊ルートを表示します。清里駅→まきば公園は14:20発・14:29着が第一候補で、QUEST DAY2のボタンで15:10発・15:19着へ変更可能。散策開始と場所名の解放、NEXT ACTIONも追従します。時刻や区間は推測で別便へ置き換えていません。

ホテル名は依頼の表記「グランドメルキュール八ヶ岳リゾート＆スパ」を使用。DAY1・3の移動も今回の行程どおりです。曖昧な朝・夕方は初回の目安時刻を維持しています。11/2は月曜日として表示し、祝日表記は付けていません。

サンメドウズ清里は11:04〜13:10、清里テラス・リフト・記念撮影、12時頃のサンダンス昼食を登録。昼食時刻は行編集で変更可。12:55は13:10発に備える**行動目安**で、交通機関の発車時刻ではありません。清泉寮は13:18〜14:02、ソフトクリーム・撮影・景色・余裕があれば土産、レストラン昼食なし。まきば公園は便に応じた滞在時間と動物・景色・散策を案内します。

15:50のバス停帰還目安と16:04発の重要バスを独立行動として管理。HOMEとQUESTに警告、帰還目安まで/発車までのカウントダウンを表示します。警告はDAY2に表示し、発車1分後まで継続します。交通時刻・乗車場所は公式再確認前として要確認です。

旧 `private/itinerary.json` / `private/transport.json` は初期版の保管用で、現在のアプリは参照しません。今後の旅程修正は公開ソースの `src/itinerary.js` か新婦モードで行ってください。

## ゲームと通知
HOME / QUEST / STATUS / ITEM / SETTINGS の5画面。HP・MP・空腹度・幸福度は現在/最大で管理。回復イベントは独立IDと出現時刻を持ち、同じIDの二重達成を防ぎます。2人の最大値成長・現在値変化を一括適用し、0〜最大値へ制限します。

情報解放とクエスト達成は別。予定時刻だけで自動クリアにはせず、ボタンで達成記録を保存します。DAY3の新規クエスト更新は9/12/15時だけ。DAY1/2は21時、DAY3は15時から現在値入力でき、後日入力も可能です。過去日への入力も現在ステータスを更新します。

15秒プロローグは5秒/4秒/6秒。初回のみ自動、スキップ・再視聴可。解放/回復/LEVEL UP/夜の入力/終了にモーダルを表示し、未確認分を再訪時にも表示。確認履歴は端末の役割別に保存します。「あとで」のイベントはSTATUSから達成可能。ブラウザを閉じた間のプッシュ通知はありません。

## ITEMのちらつき対策
チェック操作は画面全体を再描画しません。チェック状態と件数だけを即時更新し、保存中は対象だけを一時無効化。複数項目の連続操作も保留状態を保持します。失敗した項目は元の状態へ戻し、画面内のエラーと通知で案内。DOMとスクロール位置を維持します。ITEMの時刻更新・別タブ更新でも不要な全体再描画を避け、通知の表示/確認もモーダルだけを更新します。
