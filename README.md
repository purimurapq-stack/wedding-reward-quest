# 結婚式お疲れ様旅行 — クリア後のごほうびクエスト
スマホ向け旅行RPG試作品。独自の低頭身ドット絵・硬い輪郭のゲームウィンドウ・2コマアニメーション。依存パッケージなし、Node.js 20以上。

## Windowsで画面を確認
GitHubの作業ブランチ `feat/reward-quest-prototype` にある `reward-quest-preview.html` を開き、右上の **Download raw file** で保存し、Edge/Chromeでダブルクリックしてください。サーバーやNodeのインストールは不要です。これはソースから生成した架空デモです。各HTMLファイルの保存データはブラウザとファイルの場所によって共有されない場合があります。

SETTINGSのデモ日時を旅行中に変更し、HOMEへ移動するとその時点の未確認通知を順に体験できます。通知の「あとで」はその通知を確認済みにしますが、回復イベントはSTATUSから後で達成できます。日時を戻しても達成と通知確認履歴は消えません。新しくダウンロードしたHTMLでも既存の端末保存が読める場合は、それを引き継ぎます。

## 現在の仕様
- HOME：NEXT ACTIONを目立つ場所に表示。次の行動の時刻・残り時間を秒単位で更新し、時刻になると次へ。日本時間。新郎には安全な一般行動、新婦には詳細を表示。デモ時計は指定時刻から進みます。
- QUEST：DAY1〜3の旅行しおり。クエストブロックに詳細な時系列行動をまとめます。未解放・解放済み・QUEST CLEARの3状態。情報公開時刻とボタンによる訪問達成を別管理し、達成時刻を保存します。過去の予定も閲覧可能です。手動クリアで未来の詳細が先に公開されることはありません。
- STATUS：2人の現在値/最大値、時刻で出現した回復イベント、夜の入力案内、日付別の入力記録。DAY1・2は21時に入力案内、DAY3は新しい21時更新を作らず15時の終了と一緒に任意の記録を案内します。過去日も後日入力できます。過去日への保存も現在ステータスを更新することを入力画面に表示します。
- ITEM：14項目の持ち物・防寒案内・旅行の心得。チェックを端末保存。
- SETTINGS：架空デモの役割、デモ日時、アニメーション、15秒のプロローグ再視聴、JSONバックアップ。

プロローグは結婚式5秒・帰宅4秒・新クエスト6秒で、15秒後に開始ボタンが表示されます。初回のみ自動再生、スキップ可。動きを減らす設定では手動シーン送り。結婚式シーンの2コマと花びらを維持しました。

通知は解放・回復出現・回復達成と最大値成長・夜の入力・最終日終了にゲーム風モーダルで表示します。開きっぱなし/再訪時のどちらでも未確認分を処理し、確認履歴はプレイヤーごとに保存。閉じたブラウザへのプッシュ通知はありません。多数の未確認がある場合は順番に表示されます。SETTINGSの編集中とプロローグ中は通知を割り込ませません。

最終日のクエスト更新は9時・12時・15時の3回だけ。時系列の移動表示やNEXT ACTIONはそれ以降も動作します。15時のQUEST COMPLETE通知は訪問を自動達成した意味ではありません。達成記録にはボタン操作が必要です。

## データを編集
- `src/data.js`：架空の公開予定。日時・安全な一般行動・架空詳細・各行のrevealAt・クエストのactionIds・回復イベントを分離。DAY2の時刻は依頼の初期値です。
- `src/domain.js`：数値更新・時刻判定・次の行動・達成記録・通知抽出・旧保存データ移行。
- `src/storage.js`：端末保存アダプター。クラウド移行点。
- `src/visuals.js`：独自のドット絵。`characterAssets.groom/bride` に画像URLを設定すると2コマの横並びスプライトシートに変更できます。幅が1コマの2倍、高さが1コマ分の透過画像を使用。CSSの `.sheet` で1コマの表示サイズを調整できます。参考画像に合わせた作画は未実施。
- `scripts/preview.mjs`：同じソースをCSS/JS内蔵HTMLにまとめます。プレビューを直接手編集しないでください。
- `private/itinerary.json`：ローカル限定の実旅程、クエスト、回復イベント、夜の案内。Git除外・ビルド除外。
- `private/transport.json`：交通区間の編集用一覧。record IDで旅程と対応します。こちらを編集した場合、itineraryの同じIDへ時刻/区間/revealAtを反映してください。自動同期はありません。

実旅程のplannedAtは以前の依頼どおり（朝・夕方等は初回の仮数値）で、バスを調べ直したり別便へ変更したりしていません。交通は公式確認前として要確認。バスを前後させる際はplannedAt、対応区間、公開先の訪問時刻revealAt、関連回復イベントのavailableAtをまとめて見直してください。場所の名前だけでなく交通区間・注記もサプライズ情報です。

回復イベントは一意のinstance ID、effect、availableAt、questIdを持ちます。同じ種類の複数回イベントも独立して達成でき、同じIDの二重達成を防止。2人に同じ最大値成長/現在値変化を適用し、現在値を0〜最大値へ制限。空腹度は高いほど空腹。幸福度も上限あり。最大値は日々の入力では変更しません。

## 本番の情報保護とクラウド移行
**現在は架空デモ専用です。役割スイッチとブラウザ時計は認証・情報保護ではありません。本物の旅程をsrc、HTMLプレビュー、distへ入れないでください。** GitHub Pagesだけでは実旅程の秘密と2端末同期を実現できません。

推奨：Firebase Authentication + Cloud Functions + Firestore。
1. 2人のアカウントを作成し、Admin SDKでUIDへroleとcoupleIdのカスタムクレームを付与。IDトークンを検証し、リクエストで指定されたrole/UID/時計を信用しない。
2. 実旅程はサーバー専用DBへ保存。Firestore Rulesでクライアントからの旅程読み書き・ステータス直接書き込みを拒否。鍵はSecret Manager等に置き、ソースに埋め込まない。
3. 認証済みAPIはcoupleIdで所属旅行を限定。新郎にはすべての安全な行動/時刻を返し、サーバー時刻がrevealAt以降の詳細だけ追加する。新婦には全詳細。`server/policy.js` は明示的なフィールド許可リストによる投影例。注記・交通区間も隠す。未解放データをJSON、プリロード、HTML、ソースマップに入れない。レスポンスはprivate, no-store。
4. `completeEvent` はサーバーのイベント設定と時刻を検証。coupleIdの共有状態をFirestoreトランザクションで読み、IDの重複確認・2人の更新・達成記録を一括保存。クライアントの効果値は受け取らない。
5. `clearQuest` は解放済みクエストだけ明示的に記録し、イベントとは別フィールドに保持。達成操作は未来情報の公開条件にしない。`setCurrent` は本人のみ変更可、サーバー最大値の範囲を検証。通知確認はUIDごと、イベント達成とクエスト記録は共有。
6. `repository` をAPI/購読へ切り替える。Firestore購読等で2端末へ反映。Emulator Suiteで匿名拒否、他旅行拒否、役割偽装、時刻偽装、並行重複操作、未来詳細ゼロをテストしてから実旅程を有効にする。本番ではデモ時計と役割変更を削除。

現在のlocalStorageは同一端末のみ。Web Locks対応ブラウザは複数タブ更新を直列化。非対応ブラウザは単一タブ前提。旧v1のステータス・持ち物・再生履歴・達成状況を引き継ぎます。旧1日1種類の達成は対応する1インスタンスにだけ移行し、追加のおやつ等は未達成です。バックアップ復元UIは未実装。
